Create Custom Fields

Do this before touching the form. Fields must exist first.

→
Navigate to Custom Fields
Location
▼
  • Open the Noonshop GHL sub-account (not the agency view)
  • Go to Settings in the left sidebar
  • Click Custom Fields under the Data section
  • Select the Contacts tab — not Opportunities or Companies
  • Click + Add Field for each of the 7 fields listed below
Path
Settings → Custom Fields → Contacts → + Add Field
→

Name → Full Name  ·  Email → Email  ·  Job Title → Position  ·  Optical Store → Company Name
QB Sync note
Custom warranty fields are not touched by the QuickBooks sync — only standard contact fields (Name, Company, etc.) get overwritten. Your warranty data is safe.

Build the Form

Recreate the MS Forms layout inside GHL's Form Builder. Field order and labels must match the original.

→
Create a new blank form
Setup
▼
  • Go to Sites → Forms → + New Form
  • Choose Blank Form (not a template)
  • Name it: Warranty Replacement Request
  • Add a Header / Description text block at the very top with the warranty policy below
Paste this as the form header description
Warranty will cover ONLY manufacturer defect and not for damage due to lens insertion damage or customer mishandling. If damage is determined not to be a manufacturer defect, replacement frames will need to be purchased. Damaged frames MUST be returned for warranty. Any frame not returned within 14 days after receiving replacement WILL be processed as a new purchase.

Configure form settings
Settings
▼
  • Sticky Contact: Enable — pre-fills data for returning B2B contacts who have submitted before
  • On Submit action: Show inline confirmation message (or redirect to a thank-you page)
  • Thank you message text: "Your warranty request has been received. We will contact you shortly with further instructions. If you have questions, email orders@noonshop.com."
  • Disable form-level notifications — all notifications are handled by the workflow in Phase 3
3

Build the Workflow

Fires on every warranty form submission — tags, notifies, and creates a trackable opportunity.

→
Create and configure the workflow
Trigger
▼
  • Go to Automation → Workflows → + New Workflow
  • Name: Warranty Request — Form Submitted
  • Trigger: Form Submitted
  • Select form: Warranty Replacement Request
  • Re-entry: Allow — a rep may submit multiple warranty claims over time
Re-entry is critical
The same optical store contact may submit multiple warranty claims. Re-entry must be enabled so each form submission fires the workflow independently and creates a separate opportunity.
→
Workflow action sequence
Actions
▼

Trigger: Form Submitted

Fires when the Warranty Replacement Request form is submitted by any contact

Add Tag: warranty-request

Tags the contact so all warranty submissions are filterable across the CRM

Send Internal Email Notification

To: orders@noonshop.com. Includes all form field data via merge tags. See Phase 4 for the full template.

Send Confirmation Email to Submitter

Sender: Anna Park via orders@noonshop.com. Acknowledges receipt and reiterates the 14-day return policy. See Phase 4.

Create Opportunity

Pipeline: Warranty Requests · Stage: New Request · Name: Warranty — {{contact.company_name}} — {{contact.custom_field.frame_model_color_code}}

End

All further follow-up is handled manually via the Warranty Requests pipeline

→
Create the Warranty Requests pipeline
Pipeline
▼
  • Go to CRM → Pipelines → + New Pipeline
  • Name it: Warranty Requests
  • Add the 5 stages below in order

QA checklist before going live
QA
▼
  • Submit a test form with Prakash using a test email address not already in GHL
  • Verify a new contact was created in GHL with all 7 custom fields populated correctly
  • Verify the internal notification arrived at orders@noonshop.com with all merge tags resolved (no blank fields)
  • Verify the confirmation email arrived at the test email address
  • Verify an opportunity was created in the Warranty Requests pipeline at "New Request" stage
  • Verify the contact was tagged warranty-request
  • Submit a second test from the same email to confirm re-entry fires correctly — a second opportunity should be created
  • Confirm tags are not duplicated on the second submission
QB sync note
If the test email matches an existing QuickBooks-synced contact, the QB sync will overwrite standard fields (Name, Company, etc.) within ~4 minutes. Custom warranty fields are not affected by QB — they are written by GHL and QB does not touch them.
If merge tags show blank in the email
Check that the custom field keys in Settings → Custom Fields exactly match what's in the email template. Keys are case-sensitive and auto-generated — copy them directly from the GHL field tooltip rather than typing by hand.
