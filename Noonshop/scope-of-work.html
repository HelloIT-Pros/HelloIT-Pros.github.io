Section 01
PROJECT
OVERVIEW

Noon Shop is a specialty eyewear brand founded by Dr. Anna Park, MD — an ophthalmologist with over 20 years of clinical experience. The brand's core philosophy is that most eyewear fails its wearer not in style, but in fit. Noon Shop engineered two collections around three clinical fit dimensions: Bridge Fit, Cheekbone Clearance, and Face Width.

Objective
BRAND-FORWARD E-COMMERCE
Build a Shopify store that communicates the Noon Shop brand story and fit philosophy while converting visitors into confident buyers. The site must function as both a retail engine and an editorial brand platform — balancing clinical credibility with high-end aesthetic.
Primary Audience
FIT-CONSCIOUS BUYERS
Customers who have struggled with ill-fitting eyewear — particularly those with low nose bridges, prominent cheekbones, or narrower face widths. Educated, design-conscious, and willing to invest in quality when the value is clearly communicated.
Two Collections
DORMANN & STEEL BROWN
Dormann — Beta-titanium temples, patented screwless snap hinge, South Korean craftsmanship. Vibrant colors on a fit-first foundation.

Steel Brown — German stainless steel, designed with optical engineer Wolfgang Proksch. Neutral tones built for professional and everyday wear. Each collection has its own editorial identity and must be presented with dedicated landing experiences within the store.
Prototype Reference A fully designed, 5-page static HTML prototype has been developed and reviewed by the client. This prototype — built at helloit-pros.github.io/noonshopwebsite/ — serves as the visual and functional specification for this Shopify build. All features described in this document are represented in the prototype.
Section 02
PLATFORM:
SHOPIFY

The site will be built on Shopify using a fully custom theme (not a pre-built template). Shopify provides the e-commerce backend — inventory, checkout, payments, orders — while HelloIT Professionals delivers a bespoke front-end experience that matches the approved prototype design.

Theme Architecture
CUSTOM LIQUID THEME
Built using Shopify's Online Store 2.0 theme architecture. All pages will use Liquid templates, section schemas, and block configurations — enabling the client to make content updates through the Shopify Theme Editor without code changes.
  • Liquid templates for all 5 primary page types
  • Reusable section components with configurable blocks
  • JSON template files for flexible page composition
  • Global settings schema for brand colors and fonts
Shopify Plan
PLAN RECOMMENDATION
We recommend starting on Shopify Basic or Standard. Several features (checkout extensibility, B2B, advanced scripts) require Shopify Plus and are noted where relevant. Plan requirements should be confirmed during discovery.
  • Basic/Standard: sufficient for launch
  • Advanced: needed for advanced shipping rules
  • Plus: required for checkout customization beyond standard

Section 04
DESIGN
SYSTEM

The visual language is defined and locked in the approved prototype. All design tokens, typographic scales, and component patterns will be implemented as CSS custom properties and translated into Shopify's global settings schema.

Color Tokens
BRAND PALETTE
  • --ink (#0C0C0C): Primary text and dark UI
  • --paper (#EEECE7): Default page background (warm cream)
  • --white (#F7F6F3): Alternate section background (soft white)
  • --gold (#C8B89A): Brand accent on dark surfaces
  • --gold-dark (#A89070): Brand accent on light surfaces
  • --gold-light (#E8D8BE): Hover states, highlights
Typography
TYPE SYSTEM
  • Bebas Neue: Display headings, stats, product names
  • Outfit (100–500): Body text, UI labels, navigation
  • Playfair Display (regular & italic): Quotes, subheadings, editorial text
  • All sizes use clamp() for fluid responsive scaling
  • Letter-spacing and weight defined per-component in design tokens
Motion & Interaction
ANIMATION SYSTEM
  • Scroll reveal: IntersectionObserver — elements animate in on viewport entry with staggered delays
  • GSAP loader: Homepage entrance animation (sequential text reveal)
  • Custom cursor: 7px dot + 32px ring, mix-blend-mode: difference; scales on hover
  • Product image hover: Flat → on-model crossfade on product cards
  • Nav mega-dropdown: Slide-in transition from top
  • Page transitions: Smooth section entry animations
Layout Principles
LAYOUT SYSTEM
  • Editorial hero sections and footer stay dark (--ink background) for visual drama
  • Content sections alternate between --paper and --white
  • Dark collection cards and editorial panels retain dark treatment
  • 60px horizontal padding desktop, 24px mobile
  • Responsive breakpoint at 900px

Section 11
SHOPIFY
CONSIDERATIONS
& CHALLENGES

Shopify is an excellent platform for this project — but building a high-fidelity, editorial experience on Shopify requires deliberate architectural decisions. The following items are known challenges that will require specific implementation strategies. These are not blockers, but they are scoped and budgeted accordingly.

#
Topic
Challenge & Approach
Impact
01
Product Metafields for Fit Data
Fit tags (Bridge, Cheekbone, Width), Dr. Park clinical notes, and frame measurements are not native Shopify product fields. These must be created as metafield definitions in the Shopify admin and populated per product. The Liquid theme will render them conditionally. A content entry workflow must be established for the client team.
Approach: Shopify native metafields (Online Store 2.0) + metafield definitions setup + admin documentation for client
Planning
02
Fit Quiz: sessionStorage vs. Customer Accounts
The Fit Finder quiz saves results to sessionStorage (browser tab only — clears on close). This works well for anonymous browsing but the fit profile is lost when the session ends. A more durable fit profile requires either Shopify Customer Metafields (logged-in users only) or a third-party app. The current prototype uses sessionStorage — upgrade path should be scoped.
Approach: sessionStorage for launch; customer metafield persistence as Phase 2 if customer accounts are enabled
Medium
03
Collection Filtering & Fit Tag Facets
Shopify's native collection filtering supports tags and product type — but the fit tag filtering on the shop page (Bridge / Cheekbone / Width combinations) requires careful product tag taxonomy and may require a third-party filter app (e.g., Boost Commerce, SearchPie) for more complex faceted filtering beyond what Shopify's Storefront Filter API natively handles elegantly.
Approach: Evaluate Shopify native filters first; scope filter app if needed
Medium
04
GSAP & Custom Cursor on Shopify
GSAP (GreenSock Animation Platform) and the custom cursor require loading external JavaScript in the Shopify theme. This is fully supported — GSAP via CDN or npm bundle, cursor via custom JS snippet. However, Shopify's asset pipeline and theme script loading order must be carefully managed to avoid conflicts with Shopify's own JS and app scripts. Performance impact of GSAP loader should be measured and the loader should be skippable for return visitors (localStorage flag).
Approach: GSAP via CDN with defer/async; loader skip logic via localStorage; cursor disabled on touch devices
Low
05
Checkout Customization Limitations
Shopify's standard checkout cannot be styled beyond basic branding (logo, colors, font) on standard plans. The checkout page will not match the custom Noon Shop design system. For full checkout UI control, Shopify Plus (Checkout Extensibility) is required. Post-purchase pages and order confirmation are similarly limited on standard plans.
Approach: Apply basic branding (logo, gold accent, fonts) to standard checkout; note Plus as upgrade path
High
06
Product Image Flat/Model Hover (Quick-Add)
The product card hover state (flat → on-model crossfade) requires that each product has at least two images tagged or ordered correctly — one flat/product image and one model image. This must be enforced as a content management convention. If a product only has one image, the hover will gracefully show no change rather than breaking.
Approach: Image alt-text convention or Shopify image roles (metafield) to identify flat vs. model shots
Low
07
Theme Editor Compatibility
Highly custom sections (the Fit Guide quiz, the founding timeline, the homepage quiz) cannot be fully configured through the Shopify Theme Editor without building out complex section schemas. Some sections will be code-only and require developer involvement to update. The client should be aware that not all content is editable via the drag-and-drop editor.
Approach: Document which sections are editor-editable vs. code-only; build schemas for high-frequency content
Medium
08
Page Speed & Core Web Vitals
Large editorial images, GSAP, custom fonts (3 font families, multiple weights), and IntersectionObserver animations all contribute to page weight. Shopify's app ecosystem can also add significant script bloat. Image optimization (WebP, lazy loading), font subsetting, and critical CSS inlining will be required to meet acceptable Core Web Vitals scores.
Approach: Shopify image CDN for assets, lazy-load below-fold images, GSAP deferred, critical CSS inlined
High
09
Mobile Navigation
The prototype hides the nav links on mobile (<900px) but does not implement a hamburger/drawer menu. A mobile navigation drawer must be designed and built for the Shopify theme. This is in scope but the exact pattern (drawer, bottom nav, etc.) requires design decision.
Approach: Slide-in drawer nav consistent with brand aesthetic; confirmed during design review
Medium
10
App Script Conflicts & Budget
Each third-party Shopify app (reviews, virtual try-on, filter, email pop-up) injects additional JavaScript and CSS. On heavily-customized themes, app scripts can conflict with custom interactions or affect layout. Apps also add recurring monthly costs on top of the Shopify plan fee.
Approach: Vet app choices before installation; test each app in a development theme; confirm app budget with client
Medium
