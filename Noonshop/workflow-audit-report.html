This audit covers all 27 GHL workflows in the Noon Shop tenant, with deep inspection of the 5 published workflows that send emails (∼47 email actions total). Each email template was scanned via API for merge field usage, and the results were cross-referenced against the intended sender (Rep vs. Anna) documented in the workflow design.

Critical finding: The dedicated domain header had a static From Name ("Noon Shop") that overrode all workflow-level From settings, assigned user fallback, and merge field variables. This was identified, tested, and resolved on March 19, 2026. The From Name field in the dedicated header is now cleared, allowing the normal GHL sending priority to take effect.

Remaining work: Each of the ∼47 Send Email actions across 5 workflows needs its From Name field explicitly set — either to {{user.name}} (for rep-sent emails) or "Anna Park" (for founder emails).

2.3 Root Cause

The GHL dedicated domain header's "Set Headers" feature applies a hard override to all emails originating from that domain. The GHL UI itself states: "The designated header will be applied to all emails originating from this domain." When a static From Name was set ("Noon Shop"), it overwrote the workflow's From Name field, the assigned user fallback, and even explicit {{user.name}} merge field values.

This behavior differs from what the official sending priority documentation implies. There is a community feature request asking GHL to allow overriding only the email (not the name) in dedicated headers.

16. How It Should Work

Once all actions in the checklist are completed, here is the expected behavior for every email sent from GHL workflows:

16.1 Rep-Sent Emails

When a contact is assigned to a sales rep (Anna Park, David Cho, Sandra Kim, Peter Chong), workflow emails intended from the rep should display:

from:     David Cho <hello@noonshop.com>
reply-to: hello@mail.noonshop.com
to:       contact@example.com
mailed-by: mail.noonshop.com
signed-by: mail.noonshop.com

How it works:

  • The Send Email action's From Name is set to {{user.name}}, which resolves to the contact's assigned user (e.g. "David Cho").
  • The From Email defaults to hello@noonshop.com (from the dedicated domain header), keeping deliverability centralized.
  • The email body uses {{user.fullname}} for the greeting and {{ user.email_signature }} for the sign-off, both resolving to the assigned rep.
  • The calendar link uses {{user.calendar_link}}, pointing to the rep's specific booking page.

16.2 Anna-Specific (Founder) Emails

Certain emails in each journey are intentionally from Anna Park as the founder. These should display:

from:     Anna Park <hello@noonshop.com>
reply-to: hello@mail.noonshop.com
to:       contact@example.com
mailed-by: mail.noonshop.com
signed-by: mail.noonshop.com

How it works:

  • The Send Email action's From Name is hard-coded to Anna Park (not a merge field — always shows Anna regardless of assigned rep).
  • The email body uses {{custom_values.anna_email_signature}} for the sign-off (Anna's specific HTML signature).
  • Any calendar link in these emails should use {{custom_values.anna_park_booking_link}} (not the rep's link).

16.3 Unassigned Contacts

If a contact has no assigned user, the From Name will fall back to the location default:

from:     Noon Shop <hello@noonshop.com>

This is acceptable as a fallback but should be rare — all active contacts should have a sales rep assigned.
